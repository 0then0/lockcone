# Changelog

User-visible changes are recorded here. Version links lead to the published
release or the corresponding comparison of commits.

## [Unreleased]

### Added

- Peer context reports for package instances whose name and version exist on both
  sides, including changes that leave every version the same. Each change lists the
  instance keys of both sides, the providers before and after, and the events
  `provider-added/removed`, `provider-version-changed`, `nested-context-changed`,
  `evidence-changed`, and `instance-split/merged/added/removed`.
- Evidence levels for every binding: `direct` needs the peer declaration, the
  provider in the key, and a snapshot edge to it; `transitive` is a context inherited
  through a dependency edge; `unconfirmed` and `conflicting` keep their reason.
  Optional peers, nested and scoped contexts, and patch hashes are supported. Hashed,
  malformed, and oversized suffixes are kept as written and give no bindings.
- Pairing of instances through the dependents that hold them. Possible pairs are
  listed as `ambiguous` when the dependents do not single one out, and nothing is
  paired by name and version alone.
- Workspace consumers with paths for every listed instance, a `peerBindings` JSON
  section with its own `reportVersion` (currently `1`), peer evidence in
  `why`/`explain`, and a [peer context reference](docs/peer-contract.md).
- A case study of pnpm/pnpm#14895 on lockfiles reproduced with pnpm 12.4.1
  (`examples/peer-acceptance.mjs`).

### Changed

- JSON reports gain the `peerBindings` section. `schemaVersion` stays `4`, and no
  existing field, classification, or warning changes.

## [0.4.0]

### Added

- Override change reports for pnpm `overrides`, separate from version changes:
  declaration, source, and lockfile record are independent events, and a changed
  rule is matched to the dependency edges it governs on both sides, with the paths
  to the workspace projects that reach them. Supported rules are `name`,
  `name@range`, and `parent>child` selectors, scoped names included, with an exact
  stable version or a stable registry range as the value.
- The configuration source follows `packageManager`: `pnpm-workspace.yaml` for pnpm
  11 and later, `pnpm.overrides` and `resolutions` for pnpm 9 and 10. Other sources
  and unsupported values keep their warnings.
- Evidence paths that start at a governed edge, marked with `via` on the evidence
  entry. A complete rule can make the dependent and the new package `explained`;
  packages reachable only beyond the edge stay `unknown`, and unrelated updates in
  the same lockfile stay `unexplained`.
- An `overrides` JSON section with its own `reportVersion` (currently `1`), override
  evidence in text output and in `why`/`explain`, and an
  [override reference](docs/override-contract.md).
- A case study of a PostCSS override repair in nitsuah/farm-3j
  (`examples/override-acceptance.mjs`), and a registry-range intersection check
  compared with node-semver.

### Changed

- A rule that the override report interprets no longer produces the global
  `Workspace configuration changed`, `Unmodeled manifest resolution input changed`,
  or `Lockfile resolution configuration changed` warnings. A rule that is not fully
  accounted for produces an `Override SELECTOR (base|head): …` warning instead, so
  its groups stay `unknown`. Unsupported rules, hooks, unchanged `catalog:`
  overrides, and manifest/lockfile mismatches keep their warnings.
- Workspace consumer lookup is shared by the patch and override reports. Patch output
  is unchanged.

## [0.3.0]

### Security

- Update Zod from 4.6.5 to 4.6.7, which includes the fix for collection-validation
  memory exhaustion ([GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)).

### Added

- Patch change reports for pnpm `patchedDependencies`, separate from version
  changes: declaration, selector, source, file reference, exact patch bytes
  (SHA-256 of the committed blob), lockfile metadata, and unavailable inputs are
  independent events.
- Associations between patches and package instances (`lockfile-confirmed`,
  `selector-applicable`, `unknown`) for name, exact-version, and registry-range
  selectors, with peer contexts and multiple versions kept separate.
- Reverse paths from patched instances to workspace consumers on each side, marked
  direct or transitive, with uncertainty reasons and explicit limits.
- Patch evidence in text output (`explain` and `why` add full paths) and in a new
  `patches` JSON section with its own `reportVersion`.
- Fixtures generated by pinned pnpm releases (`examples/patch-fixtures.mjs`) and an
  external case study of radix-ui/primitives (`examples/patch-acceptance.mjs`).
- A [patch reference](docs/patch-contract.md) and
  [0.3 release notes](docs/release-notes-v0.3.md).
- Monthly Dependabot checks for GitHub Actions, with grouped minor/patch updates,
  a single open version-update PR, and a seven-day cooldown.
- EditorConfig settings and Git attributes that preserve fixture bytes.
- Bug report and feature request forms, a pull request template, a code of
  conduct, and a security reporting policy.

### Changed

- Patch files are read from committed blobs as raw bytes and compared by digest or
  Git blob ID. A symlink, submodule, or out-of-repository patch path is reported
  as unsupported instead of being read, with a `Configured patch file is
  unsupported` warning. Patch files above 8 MiB are not read.
- The project icon shows the lock, the cone, and the unreachable node more clearly.
- Ignore rules now cover the project's build output, release archives, local
  caches, and environment files without unrelated framework rules.
- CI cancels superseded runs; CI and release jobs have explicit timeouts.
- Contributor and release documentation links to the project policies and changelog.

## [0.2.0]

### Added

- Default and named pnpm catalogs in runtime, development, and optional dependencies.
- Declaration intent and origin evidence for catalog-only updates.
- Consistency checks for catalog entries, snapshots, and importer resolutions.
- Catalog context in `why`, including changes to resolution alone.
- A reproducible ni case study with pinned inputs and baseline comparisons.

### Changed

- JSON reports use schema v4 with `declarations`, `declarationChanges`, and
  `catalogChanges`. Schema v3 output is not available.
- Catalog origin changes with the same effective range do not create traversal
  roots. Resolution-only changes do not become declaration intent.
- Supported catalog updates no longer produce blanket configuration uncertainty;
  unsupported or inconsistent evidence remains conservative.

See the [v0.2 release notes](docs/release-notes-v0.2.md) for compatibility and limits.

## [0.1.0]

### Added

- `diff`, `explain`, and `why` commands for committed pnpm v9 dependency graphs.
- Old/new graph traversal, workspace handling, evidence paths, and text/JSON reports.
- Conservative classification for peer context and unsupported resolution inputs.
- A composite GitHub Action and release archives with SHA-256 checksums.
